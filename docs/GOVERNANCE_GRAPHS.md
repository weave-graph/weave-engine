# Native accepted-governance graph values

`Engine::query_accepted_view(&AcceptedViewSelection { view_id, decision_id }, host)` returns the exact accepted source graph with real decision assertion influence. `decision_id: None` captures the current head once; a specified occurrence selects its historical source. Both use current policy and current source authorization at the [trusted operation time](OPERATION_CLOCK.md). This native host API does not add a language operator or change protocol 0.15.

New successful publications create one immutable genesis graph in `weave:governance:decision:<opaque decision occurrence>`. Its fixed explicit schema has one decision node, one structural self-relation, a positive `accepted` assertion, and a pinned source attachment. The node contains only view identity, opaque occurrence, action kind, and trusted acceptance time. No member roster, quorum count, approval signature, policy commitment, proposal digest, or predecessor chain is exposed in GraphData. Its assertion interval describes the historical event; it is not an active grant.

A private registry binds the exact graph/revision, occurrence, view, action, original source/branch, publication occurrence and content digest. The runtime verifies the immutable graph against that binding and its SQL decision. A separate exposure marker prevents a missing registry entry from falling back to the older SQL-only inspection profile. Serialized graph IDs, schema labels, source labels, and predicates cannot install this association. Administrative database modification can destroy or rewrite these anchors; the integrity checks do not claim protection from such an administrator.

Policy transitions create their own records when inheriting an exposed publication. An accepted value after transition retains both the current decision assertion and the original publication assertion. Historical selection preserves its own publication, while its permissions always come from the currently installed policy. Historical vote expiry does not independently invalidate an authorized read; mutation receipt retries still require the original proposal and a currently valid quorum.

## Authority and composition

One common protected-reference gate now combines installed identity and governance policy checks wherever native graph references are read. A governance reference requires an active current policy, an authorized reader, its original source revision reachable from its recorded branch under current allowed scopes, and full current authorization of the pinned source's metadata and proof closure. Source authorization includes global and per-alternative assertion/node gates and typed-context carriers. A pinned occurrence never preserves old read permissions.

The first profile requires the whole source closure to be visible. It rejects live handles rather than approving future target revisions. New acceptance containing any reachable `LiveGraph` fails atomically. Pinned cyclic metadata is bounded by visited snapshots; cyclic proof dependencies remain unavailable. Protected record recursion is bounded to 32 active references and shares the enclosing operation's cumulative read count/byte budget. Metadata/proof closure has a 1,000-snapshot and 10,000-queued-reference bound. Registry bodies are SQL-limited to 64 KiB before parsing. New registry and graph payload bytes participate in the existing per-view governance quota. No process-memory, timing noninterference, or guaranteed-progress claim follows from these logical bounds.

An accepted query preserves original source object IDs, payloads and origins. Acceptance is an additional whole-value AND influence, including on an empty result. The existing portable operators propagate it; generated `Support`, `Explain`, and geometry nodes retain their own decision proof gates when the whole carrier and readers are removed. An independently public original fact remains readable independently of the acceptance label. There is no declassification operation.

The same current gate applies to pinned queries, assertion/structural resolution, metadata and provenance traversal, saved derived values, current/prior cached view transitions, signed read receipts, capsule export, graph-event dispatch, handler receipt replay and typed governance delivery. `AllowStale` allows older data, never old authority. Decision and source heads do not need to move for policy expiry or revocation to block these paths.

## Storage, transport and recovery

SQLite marker **12** adds the protected registry and exposure markers transactionally. An older marker-11 binary refuses the store before migration or data access. Existing graph bytes/hashes, receipts and SQL-only decisions are not rewritten or backfilled. Legacy native inspection remains available under its original current-authority boundary; `query_accepted_view` requires a genuine exposed occurrence. A fresh publication is needed after a legacy-only decision. A policy transition over such a legacy publication does not synthesize a graph proof.

Decision graph, structural/schema registrations, protected binding, head CAS, governance decision, receipt and both outboxes commit together. A genuine decision graph mutation emits a normal `graph.committed` event; `view.accepted` / `policy.changed` remain separate typed governance events. Exact authorized retry adds neither. This explains the updated source-plus-decision event assertions in recovery tests.

Raw commits/batches, fork/accept, generic capsule receipt, signed publication/integration and adapter outputs cannot write reserved decision storage. Altered reserved schema descriptors are rejected; an exact fixed descriptor may accompany an ordinary materialized copy. Export can archive currently authorized records, but generic peer receipt rejects protected decision graphs. No remote registry installation, authority portability, or receipt of an unsigned capsule as trusted governance is supported.

## Acceptance evidence

- [Native matrix](../crates/weave-engine/tests/governance_graph.rs): genuine assertion lookup and opaque minimal record, current/historical transition obligations, empty values and reader/carrier-stripped Support/Explain/geometry scalars, source-policy revocation, pinned branch reachability, proof cycles, registry corruption/removal, legacy migration, one clock sample, stale views, unrelated handler receipts, signed cached retries, delivery acknowledgment expiry and reserved peer rejection.
- [Governance process death](../scripts/check_governance_recovery.py): exit before outer commit leaves no protected graph/registry/schema/head/receipt/outbox changes; exit after commit returns the same occurrence and graph after restart; expired current policy denies graph access. `--older-engine PATH` additionally tests an actual marker-11 binary against the marker-12 store.
- [Delivery recovery](../scripts/check_governance_delivery_recovery.py) and [migration recovery](../scripts/root_migration.py) retain atomic acknowledgment and DDL rollback invariants.
