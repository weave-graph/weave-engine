# Exact decimal and nominal quantity modules

Status: protocol 0.12 portable modules, schema variants and runtime version gates implemented; paired source release is checked separately. No runtime conversion service or authority claim follows from this arithmetic module. The recovered language paper §4 requires decimals and typed quantities but does not prescribe these implementation limits.

Decimal values are exact signed coefficient × 10^-scale, with at most 18 coefficient digits and scale 0–18. Zero is unique; canonical display and serde values are decimal strings without exponents or redundant fractional zeroes. Parsing accepts bounded decimal/exponent spellings, at most 128 bytes and exponent magnitude 128. No operation passes through Float. Exact add/subtract/multiply/divide return precision, scale, divide-by-zero or nonterminating-division errors; no rounding or saturation occurs. The Decimal type is distinct from finite binary64 Float.

`UnitDescriptor { dimension_id, unit_id, revision }` is nominal identity. All three nonempty bounded identifiers must match for quantity addition/subtraction. Matching spelling, familiar symbols or equal numeric values do not establish compatibility. A Quantity contains an exact Decimal amount and descriptor. Scalar multiplication/division preserves its descriptor. General products or quotients of two quantities, dimension exponent algebra, vectors and affine units are not implemented.

`RationalConversion { from, to, numerator, denominator }` explicitly states a positive rational scale between exact descriptors sharing the same dimension identifier. Its source must exactly match the quantity's descriptor. Numerator and denominator are canonical Decimal values, so no JSON number loses precision. Conversion first cancels rational factors, then requires a finite representable exact result. For example, amount 3 times 1/3 returns 1, amount 1 times 1/3 errors, and a large quantity times N/N remains unchanged without an intermediate precision failure. A zero or negative conversion factor is invalid. Offsets are unsupported and rejected by strict deserialization.

Descriptors and arithmetic factors are claims supplied by a caller. This module neither authenticates them nor grants a capability. A later graph service must bind conversions to authorized positive assertions, exact descriptor revisions, applicable time/context and provenance; reject private, stale or incompatible evidence; and retain those restrictions in reusable graph results. The service must not silently assert identity alignment or geometry authority from unit conversion.

The implementation uses bounded standard Rust i128 operations and no new dependencies. A raw coefficient product has at most 36 digits, below i128 capacity. Reduced denominator factorization is bounded by the 18-digit divisor; powers are constructed with explicit result bounds. Canonical serde rejects unknown fields and invalid descriptors, but callers remain responsible for a total document byte limit.

The integration harness tests the exported portable modules. Twelve tests cover decimal boundary/canonical behavior, a 6,561-pair arithmetic grid, exact descriptor mismatches, scalar operations, positive rational conversions, cancellation before precision checks, unknown affine fields, malformed numeric values and a 3,600-case rational scaling grid. Native tests, strict Clippy and a WASM test-target check passed. No browser execution, full unit algebra or graph-service integration is claimed.


Schema delta: `ScalarType::Decimal` serializes as `"decimal"`; `ScalarType::Quantity(UnitDescriptor)` serializes as `{"quantity": {"dimension_id":...,"unit_id":...,"revision":...}}`. Existing scalar strings and old schema bytes remain unchanged. Decimal properties must deserialize as canonical Decimal strings; Quantity properties must carry the exact schema descriptor. Nullable behavior is unchanged. The runtime rejects either new schema type under a protocol earlier than 0.12 before any writes. Native acceptance covers canonical persistence in nodes and edges, single/batch commits, capsule receipt, old-version rejection, descriptor mismatch and whole-program rollback. No implicit Float fallback is permitted.
