# Contract 0.17.0: exact snapshot influence

Protocol 0.17 adds conservative whole-snapshot restrictions, including empty snapshots. It does not add graph ACLs, grant authority, authenticate authors, or implement compiled reactors.

`GraphInfluence.snapshots: Vec<GraphRef>` is a whole-value AND carrier. `Node`, legacy `Edge`, explicit `Assertion`, and `MetadataAttachment` each add `derived_snapshots: Vec<GraphRef>`. Attachments also add `derived_from: Vec<AssertionRef>` and `derived_nodes: Vec<NodeRef>` so detached graph-host payloads retain all three kinds of restriction. Every new field defaults to empty and is omitted when empty. Existing serialized values and their hashes remain unchanged.

A snapshot gate means that its exact immutable revision exists, passes stored integrity checks and current protected-graph policy, and remains wholly visible to the current principal. It does not follow a later head. Losing any object, proof alternative or meaningful explanation field denies the whole gate. The existing comparison permits only order/duplicates in the flat assertion index derived from unchanged OR groups. Ordinary queries still return their authorized partial subset; snapshot gates intentionally require the whole referenced value. An ordinary empty graph has no object readers and no invented graph ACL. Its gate proves exact availability and any actual protected/influence restrictions, while signed admission separately requires read/traverse scope.

Snapshot gates are global AND restrictions outside alternative derivations. A denied or cyclic gate returns generic partial output without its carrier, identifiers or counts. Genuine corruption can remain an integrity error. Ordinary metadata cycles remain data; Snapshot → Node/Assertion/Attachment/typed-context/protected-callback → Snapshot proof cycles fail closed. Repeated shared ancestors are not active recursion and remain valid.

Consuming operators retain explicitly declared snapshot gates from authorized input records in the output carrier, including when filtering produces an empty graph. The new explicit attachment assertion/node gates also survive consumption. Descriptive `input_snapshots`, ordinary metadata links, and ordinary node/edge premise indexes are not automatically upgraded into whole-snapshot authority. Generative operators put the retained gates on generated nodes, assertions and movable attachments, so deleting the envelope or readers does not release derived scalar values. Original pinned records keep their payload identity; changed values use derived wrappers. Explain represents snapshot premises as snapshot records, never invented assertion IDs.

Native authorization joins one operation-scoped traversal session across protected callbacks. It permits at most 10,000 actual proof visits and 32 active proof keys, with the previous per-chain limits retained. Ungated records consume no artificial proof visits. Active keys are removed with unwind-safe guards; work is shared through nested reads, including cached-result checks. Existing cumulative SQL read and serialized output budgets also apply. There is no process RSS or timing-isolation claim.

Combined raw assertion/node/snapshot reference counts are bounded before deduplication (1,000 per carrier or record; attachment origin also consumes capacity). Decode lists are bounded; graph/revision IDs remain at most 512 UTF-8 bytes. Incremental selection excludes these gated profiles and falls back to authoritative full evaluation.

## Compatibility and transport

Programs declaring 0.1–0.16 reject any nonempty new field before writes, including later Commit/CommitBatch commands. Literal property keys with the same names remain inert. Store marker 15 prevents old binaries opening records with new authorization semantics. Migration updates the marker atomically without rewriting old rows, revisions, compiled templates, source manifests, caches or receipts. Legitimate compiled templates declaring 0.16 retain their original identity; new templates use 0.17.

Capsules containing any new field use `weave-capsule-0.3`. Their closure includes all declared snapshot, assertion and node pins. Capsules 0.1/0.2 reject the new fields; exports with no new fields retain their old format. Received content remains quarantined until ordinary explicit acceptance. Signed export response format 0.1 remains unchanged: new responses bind contract 0.17 and actual capsule format. Historical signed contract-0.16 responses can replay byte-for-byte only with an old-compatible capsule, current proof/pairing authorization and full current closure checks. A 0.16 header cannot describe 0.3/new-field content.

Native tests cover whole versus partial visibility, exact pins, missing empty sources, mixed cycles and diamonds, hidden-record isolation, movable attachments, old-wire atomic rejection, capsule downgrade refusal, signed scope narrowing, and current protected policy expiry through cached values. `scripts/check_snapshot_migration.py` uses preserved real 0.16 binaries to populate a compiled view and signed receipt in one database, then checks precommit and postcommit process death, unchanged rows/identities, exact historical replay and old-binary refusal. Portable tests validate empty propagation, generated scalar gates, attachment carriers, bounds and snapshot explanation identity. These are prerequisites for a later compiled reactor stage; they do not close the broader paper gates.
