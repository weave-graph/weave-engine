# Contract 0.6: explicit source assertions and computation identity

An explicit graph sets `profile: "explicit"` and stores separate `structural_edges` and `assertions`. Structural edges contain stable ID, predicate, endpoints, optional type, structural properties, metadata and readers. Assertions contain their own ID, structural edge ID, claimed source label, optional pinned context graph, validity, polarity, assertion properties, metadata, readers and derivation groups. A structural relationship with zero assertions supplies no implicit positive claim. Explicit graphs reject legacy `edges`; legacy graphs reject explicit records. Omitted profile and new empty fields preserve older snapshot bytes/hashes.

Structural endpoint/predicate identity and assertion source/structural binding remain immutable across revisions and deletion. Database migration 6 backfills these registries. Edge, assertion and attachment IDs are disjoint within an explicit snapshot. Contextual assertions remain queryable and composable by union/projection; matching support/join inference fails with `E_CONTEXT_REQUIRED` until an explicit context selector is available. Source labels record claimed provenance; they are not authenticated remote identities. Replication of the same immutable snapshot is idempotent and never creates another source assertion.

Queries materialize each visible source assertion as a graph-value edge whose ID is the assertion ID. `structural_ref` pins the original relationship, while `assertion_source`, `assertion_context` and `assertion_properties` preserve attribution distinct from structural properties. Source assertion provenance remains an explicit premise on materialized values, including when a value is persisted. Structural, source-assertion and endpoint readers all constrain visibility. Alternative derivations remain OR groups of AND premises.

Named metadata can target an assertion. Structural-host attachments are materialized as collision-checked per-assertion attachments, with exact original attachment origins; select their materialized host when consuming a graph value. This access path inherits the claim's interval. Exact host APIs `resolve_structural` and `resolve_assertion` expose first-class stored objects independently; a structural object can be read even when it has no supporting claim. General structural-pattern language queries are a later profile.

Schema edge definitions validate structural endpoint types/properties even with zero claims. Assertion properties remain untyped JSON in this profile. Schema descriptors are graph-level caller-visible validation contracts in the current local reader model; there is no separate schema confidentiality or remote discoverability policy.

`Program.source_revisions` records compiler source/function revision labels and digests; queried and bound results retain them. Conflicting labels within a plan reject, and manifest size is bounded. These are attribution inputs, not execution authority or a signature. Portable identity helpers hash normalized IR, source/schema revisions, exact snapshots and explicit host visibility context. Normalization does not reorder command effects or equate arbitrary algebraic programs. Graph-valued `explain` preserves separate alternative and joint-premise groups and the input's principal scope/coverage. Plain host view registration currently takes expanded IR; richer source-manifest view registration remains a follow-up.

The CLI and import API are still trusted host boundaries. The signed admission facade is separate work: especially, trusted import currently registers immutable identities during quarantine, which must not be reused as a propose-only remote API without resolving namespace/registry poisoning. Capsule transport of explicit assertions retains raw profiles and their metadata/provenance dependencies.
