## Gaps that block the three goals

### Core (blocks all goals)

1. **Every commit stores a full snapshot.** `revisions.data` holds the whole
   `GraphData` as JSON (`weave-engine/src/lib.rs:249, 804-812`). The only write is
   compare-and-swap of a complete snapshot (`Command::Commit`). There is no API to
   add or retract one fact. Each commit also loads and compares the previous
   snapshot. Storage and write cost grow with graph size, not change size.
2. **Hard per-graph caps:** 100,000 nodes or edges per graph
   (`lib.rs:2599`), 16 MiB per stored revision (`lib.rs:803`), 16 MiB per request.
3. **Reads load and re-parse the whole snapshot**, then filter in memory
   (`lib.rs:844-1024`). There are no indexes by entity, predicate or time.
4. **Recorded-time selection walks the history chain linearly**
   (`recorded_history.rs:370-378`).
5. **Nodes have no valid time.** Only edges, assertions and attachments do. A
   unit's installation and decommissioning, or a firmware property, cannot be
   time-scoped on the node itself.
6. **Provenance is weak per fact.** The writer is recorded per commit
   (`events.actor`). `Assertion.source` is a claimed label
   (`assertions.rs:53-54`). There is no per-fact method, model version or
   evidence link recorded by the engine.
7. **There is no k-hop traversal.** `QueryPlan.from` is a one-hop edge filter;
   `max_depth` is metadata depth (`weave-contract/src/lib.rs:196-214`).
8. **"What changed" is computed, not stored.** `Diff` compares two materialized
   results (`algebra.rs:596`). There is no change log or change feed by time range.

### G1: hardware temporal graph

- There is no telemetry or series concept beyond the generic
  `MetadataValue::Artifact{uri,digest}`.
- There is no hardware reference schema or worked domain example. The examples
  are toy graphs.
- Measured scale is 10k–100k objects on one host (`docs/benchmarks/`).

### G2: agent fact store

- **No network service and no authentication on the main API.** The principal is
  whatever the embedding host passes in (`HostContext`, `lib.rs:147-160`). A grep
  found no HTTP, gRPC or MCP server.
- **No groups, roles or teams.** Every reader list holds literal principal strings.
- **No graph-level read ACL.** Any principal can query any graph; only
  per-record readers filter. `Discover` is defined but never checked, and
  `Traverse` is never distinct from `Read`.
- **Derived-fact leakage is guarded at read time only.** A writer can commit a
  derived fact with public readers and no `derived_from`, and nothing detects it
  (`docs/INFLUENCE.md:16`). Science analytics outputs (scores, neighbors) carry no
  dependency references.
- **Noninterference coverage is a finite set of paired tests**, with no
  property-based harness.
- **Signed publish forces private readers** (`admission.rs:686-700`), so there is
  no "share with team" write path.
- **No read audit log.**

### G3: hybrid RAG

- **Two disconnected vector mechanisms.** Science kNN reads an untyped node
  property `vector` with no encoder descriptor and no valid time
  (`weave-science/src/algorithms.rs:405-502`). The typed, time-aware
  `weave-spaces` model supports only pairwise distance.
- **kNN is not time-aware.** `NearestVectors.valid_at()` returns `None`, and
  time-filtered queries drop isolated vector nodes (`lib.rs:1003-1020`).
- **No vector operator in the plan algebra.** `GraphExpression` has no kNN
  variant, so vector-to-graph and graph-to-vector composition is client-side glue.
- **No candidate-relation output** (similarity edges with provenance) and no
  hybrid scoring.
- **No approximate index.** Search is an O(N·d) scan with a full sort.
- **Embedding updates require re-sending the whole graph**, which fits roughly
  1k vectors of 1536 dimensions under the 16 MiB cap.

## Documentation findings

- The README, docs index, STATUS and science guides agree with the code
  (science 0.1.0, contract 0.21.0, store 29). No relative links are broken.
- **Stale:**
  - The `IMPLEMENTATION_PLAN.md` module table lists crates that do not exist
    (`weave-model`, `weave-store`, `weave-query`, `weave-bus`, `weave-adapters`,
    `weave-sync`).
  - `workflow.json` shows E10 as in progress rather than deferred.
  - `CAPSULES.md` describes capsule 0.1 as unsigned; the code has 0.4 and
    signed export.
  - Contract v0.16, v0.18, v0.19 and v0.20 READMEs call themselves "candidate"
    or "unpublished".
  - The ADR-0001 and ADR-0002 status lines are out of date.
  - Several implemented proposals still say "pending" or "not passing".
- **Issue bodies are evidence ledgers.** They append checkpoint logs rather than
  stating remaining work and acceptance criteria, so they cannot tell a
  contributor what to do next.
- **Language:**
  - STATUS.md is a 488-line version ledger.
  - Many docs present protocol 0.14–0.19 as current; the code emits 0.21.0.
  - The plan lists crates that do not exist (`weave-syntax`, `weave-types`,
    `weave-ir`, `weave-eval`, `weave-lsp`).

## Local environment note

On the audit machine, `cc` on `PATH` (`~/.local/bin/cc`) is not a C compiler, so
builds failed at link time. Setting `CC=gcc` and
`CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_LINKER=gcc` fixed it. This is a
machine-specific issue, not a repository defect.
