# General graph-value influence — design proposal, no version reserved

The typed-context carrier solves a particular empty-value dependency problem. Governance needs the same persistence property without misrepresenting acceptance as a context type. Propose a separate optional `GraphData.influence: GraphInfluence { assertions: Vec<AssertionRef>, nodes: Vec<NodeRef> }` in a future explicit wire version. Both lists are conservative AND gates, exact pinned references, canonical/deduplicated, with a combined maximum of 1000 and existing incremental byte budgets. An empty carrier is omitted. This proposal does not install authority from its reference strings.

Every original or derived graph value, including a graph with no objects, can retain the influences used to compute its boundary. Query and every direct assertion/structural/node resolver authorize the carrier before exposing data; missing/denied/cyclic influence yields an empty carrier-free value with generic partial coverage. Native query operations that require an exact accepted authority return an explicit generic unavailable error instead of manufacturing complete empty evidence. Current source/policy authority is checked at every use, including cache, stream, receipt, capsule and signed traversal paths.

Union retains both influence sets even when no visible object remains. Filter/projection/diff/rules/metadata and persistence cannot discard them. Generated record nodes additionally receive the same assertion/node gates, and each generated assertion alternative receives the relevant assertion gates; this protects copied scalar values after their surrounding carrier is removed. Limits are charged before collection expansion. This deliberately permits false denial for mixed private/public results; an OR release optimization needs an independent proof and versioned semantics.

Governance decision references must refer to real immutable assertion/node records. The native-only approval stage currently uses isolated SQL records; it must not mint fake AssertionRefs into that table. A later integration can atomically create a genuine decision snapshot in a reserved kernel namespace, with assertion identity, approval/proposal/policy/source pins and actor/acceptance time. It must expose only authorized decision data, exclude private voter membership/counts from public fields, and attach original source proof gates. The namespace is guarded against raw commit, batch, capsule import, fork and revision-accept poisoning. A current governance-policy guard must apply at every reference resolution path, as the current identity-policy guard does. These hooks require separate adversarial review.

An accepted-view query would then add its real decision AssertionRef to the general graph influence, even when the source result is empty. It cannot label a historical pinned decision as the current accepted head. Current policy controls read authority; the historical decision retains the exact policy/approval state under which it was admitted. Policy expiry/revocation and changed source access cannot be bypassed by a cached result or a saved reader-cleared node.

Typed-context witnesses remain semantically distinct and continue to describe type selection. They may contribute their assertion/node references to the general carrier but must retain full type meaning separately. No GraphData field can self-install a policy root or register an arbitrary evaluator. Future non-graph policy evidence requires its own typed verification boundary; do not silently coerce it to an AssertionRef.

Acceptance: empty accepted source -> project/union -> Support -> persistence; generated-node copy with carrier/readers removed; direct/pinned/current-head reads; current-policy changes without source-head movement; hidden dependency noninterference; signed scope narrowing/retry; whole capsule closure; reference cycles/budgets; malformed raw carriers; atomic old-wire rejection; reserved-namespace poisoning; actual process-death at decision-snapshot/outbox/receipt commit. Root must approve exact carrier and decision namespace semantics before shared code or a protocol version is reserved.

## Required gate map before reserving a protocol version

| Boundary | Assertion influence | Node influence | Empty or unavailable influence |
| --- | --- | --- | --- |
| Direct graph query and metadata resolution | Authorize every exact source assertion under current policy before returning the carrier or generated facts | Authorize exact NodeRefs including primitive visibility, transitive proofs, and current policy | Denied carrier yields a generic partial empty envelope; no selected pin, private carrier count, or schema descriptor |
| Direct assertion/structural resolution | Resolve the assertion's own global AND gates and at least one authorized alternative | Resolve node dependencies on each alternative, independent of output endpoint visibility | Missing dependency cannot masquerade as complete absence |
| Generated node/scalar output | Materialize whole-value assertion influence into node `derived_from` | Materialize whole-value node influence into node `derived_nodes` | Even `unknown`, counts of zero, and explanation nodes inherit all influencing empty inputs |
| Generated assertion output | Include carrier assertion gates in every OR alternative's AND group; preserve existing leaf premises | **New explicit per-alternative node premises are required.** Endpoint gates alone are insufficient if a later operator changes endpoints | Every alternative retains influences even when its positive assertion-premise set is empty |
| Union/filter/project/diff/rules/join | Canonical merge of all influencing carriers, without upgrading missing completeness | Preserve both reference kinds through transformation and derivation construction | Filtering away all objects does not erase input influence; missing metadata retains the source carrier |
| Persist/export/import/capsule | Validate reference bounds and traversable current-policy closure; capsule closure contains actual immutable evidence records | Transport exact referenced source nodes/revisions and their transitive evidence | Empty carrier is serialized; quarantine is not policy acceptance; import cannot create privileged decision authority |
| Signed query and response-loss receipt | Check all influencing original dependency snapshots under the fresh grant | Require fresh read/traverse scope for node-proof dependencies too | Cached response cannot return a previously wider carrier when policy/grant changed |
| Live views, transitions, dispatcher payloads | Revalidate both current and prior influence under current host authority | Revalidate node and policy dependencies even without source-head movement | AllowStale permits stale data only, never stale authority or leaked empty-status information |

The wire design must add node premises to assertion derivation groups (for example `Derivation.node_premises: Vec<NodeRef>`) and an explicit global AND node gate on generated edges where no alternative groups exist. A flattened assertion-only provenance index cannot substitute for this representation. Alternative authorization is OR across complete groups, AND across both assertion and node refs within a group. Generated-edge identity and all proof budgets must include the new node premises. Both query and direct assertion resolution must enforce these gates; public replacement endpoints must not remove the dependency.

Original immutable source records must not be relabeled as new source evidence merely because a whole-value carrier was applied. An independently authorized original fact remains an original fact; a result that claims selection-dependent membership, acceptance, absence, count, or relevance must use an explicitly derived wrapper with the carrier materialized in its proofs. Operators must either preserve an original record's exact payload plus the enclosing carrier, or create a derived wrapper with distinct identity and both kinds of proof gates. They must not return altered payloads under an unchanged pinned origin. Tests must cover original-record copies separately from generated wrappers and prove composition cannot turn conditional membership into an unconditional conclusion.

Governance decision references will require real immutable graph assertions created only by the acceptance transaction, a reserved namespace protected on commit/import/acceptance, and current-policy checks in graph, assertion, node, capsule, cache, view, and dispatcher resolution. SQL decision identifiers alone must never be presented as graph assertions. Historical signatures prove admission at the decision point; current policy controls disclosure now. A caller-provided carrier cannot install a decision or select a stale policy as authority.

This is a design proposal, not an implemented protocol. Runtime governance remains native inspection only until this complete gate matrix is implemented and independently reviewed.
