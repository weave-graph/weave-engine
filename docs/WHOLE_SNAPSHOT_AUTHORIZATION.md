# Whole-snapshot authorization comparison

A query may return a visible subset, but capsule export/acceptance, proposal integration, required metadata, governed sources, cached result release and adapter delivery require the complete stored value to remain authorized. These boundaries use the same comparison after current authorization. An incomplete result or any removed record still fails.

Authorization recomputes a derived assertion's flat `derived_from` index from its retained alternative groups. The index is a set-like compatibility lookup; group boundaries carry the AND/OR meaning. Recomputing it can reorder or deduplicate entries even when every alternative remains visible. The comparison accepts only that index permutation/deduplication on legacy edges or explicit assertions with nonempty derivations. It checks equal reference sets, restores the original index in the temporary authorized copy, then compares the entire graph exactly. The bounded set comparison does not mutate the stored revision, capsule, digest or returned historical event.

Everything else remains exact: alternative order and boundaries, assertion and node premises, parameters, input snapshots, global gates, nodes, readers, attachments, schemas and whole-value carriers. In particular, authorization can prune an unrelated `input_snapshots` entry without marking query coverage partial; this still fails whole-snapshot comparison. Plain assertions without derivations receive no normalization. Signed capsule versus stored revision integrity comparisons remain byte/structure exact.

The regression suite covers legacy and explicit assertions, duplicate and reordered flat indexes with unchanged export/import/re-export bytes, withheld joint evidence, private assertion/node alternatives, and pruned explanation snapshots. The existing-API three-peer trace exercises the same correction through a persisted metadata-derived warning, adapter delivery, signed proposal integration and governed source acceptance.

Adapter polling durably checkpoints skipped snapshots. Existing adapters that already skipped a proof-order event do not automatically replay it after this correction. A trusted host can deliberately install a new authorized adapter identity with the intended subscription and process its historical events under current authorization. This creates a new handler/idempotency scope; the host must account for any prior effects. This fix does not rewind cursors or implicitly redeliver genuinely denied history.
