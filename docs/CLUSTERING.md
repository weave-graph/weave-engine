# Lazy topology clustering foundation

`weave-cluster` provides an I/O-free navigation hierarchy over a **trusted host's already authorized snapshot**. It does not authenticate a caller, resolve graph references, grant visibility, persist results, or execute exact queries. A host must select visible nodes and positive relations, exact context and valid time before invoking it. All returned memberships, labels, counts and source references retain that host's disclosure restrictions. Constructing a `Snapshot` from JSON is not authorization.

The initial algorithm `weave:topology-matching:1` sorts visible adjacency pairs, chooses a deterministic maximal matching and combines each matched pair. One `advance` materializes one level. Unmatched objects remain available. Each successful level strictly reduces the frontier; a level without any connecting relation records the available evidence boundary. Self-links never manufacture additional depth. There is no semantic depth constant. Separate relation perspectives can create overlapping organizations; each individual hierarchy is acyclic. This topology baseline makes no community-quality, Leiden, embedding, hysteresis or global optimality claim.

Clusters are addressable records with direct children, original members, contributing source-link IDs, algorithm level and stable membership identities and separate record revisions. IDs depend on the algorithm, perspective, exact context and visible member IDs. They do not hash an entire underlying graph revision, so a private-only revision does not perturb an otherwise identical authorized layout. A membership ID is not a complete record cache key: different decompositions can share a member set. Each record therefore has a separate digest binding its children, evidence links, level and canonical authorized source snapshot. Consumers must use both ID and revision when caching a record. The source envelope still records the true input pins. Reproducibility is for the same authorized input and version, not a claim of globally identical peer layouts.

`zoom` returns direct members; `evidence` pages through original contributing links. Aggregate directed relations retain every contributing source link and mean **at least one** such relation. The manifest marks navigation approximate, retains partial-input status and distinguishes evidence exhaustion from budget errors. No camera API or approximate exclusion API exists. Exact queries must continue to inspect authorized source evidence or use an independently sound index. The original authorized node, link and proof-reference sets remain accessible; construction only canonicalizes their ordering.

The current host limits are 10,000 nodes, 100,000 links, 16 MiB serialized input, 32 MiB stored cluster records, 256 proof references per input link and 2,000,000 logical matching-work units. Hosts can lower the work limit. These are operation limits, not a bound on all allocator overhead or CPU instructions. Serialization limits use a streaming counter. Matching uses two relation passes per level plus ordered maps, not one full relation scan per new cluster. A failed level leaves the navigation frontier and cluster records unchanged; attempted work remains charged. Evidence pages contain at most 256 IDs.

Seven independent tests cover recursive expansion with a disconnected evidence boundary, exact leaf/evidence preservation, canonical-order reproducibility, unchanged visible layout across private-only source revisions, directed aggregate relation witnesses, overlapping perspectives, malformed provenance and explicit budget/partial behavior. The privacy test assumes the host supplied identical authorized facts; it is not a full runtime noninterference proof.

The native authorized graph-service now materializes navigation values; see [CLUSTER_SERVICE.md](CLUSTER_SERVICE.md). Source query operators and graph-valued navigation are implemented. Pure frontier lineage and bounded synthetic quality/recall checks are documented below. Still required for E13: authorization-checked persistent lineage integration, event-driven incremental updates, hysteresis and broader task-quality/recall acceptance. This crate is an experimental foundation, not completion of automatic clustering or semantic zoom delivery.


## Frontier lineage and measured synthetic behavior

`Hierarchy::lineage_to` compares two complete materialized frontiers from the same perspective, exact context and **single source graph-ID domain**. Revisions and evaluation instants may differ and are recorded explicitly. Plain leaf IDs cannot establish identity across several source graph domains, so that case rejects. A trusted host must reauthorize both historical and current inputs before releasing any old label, count or membership. This pure API has no storage/policy access and is not yet exposed as an authorization-checking native service.

Sparse overlap follows common leaves to their old/new owners, with at most one overlap entry per common leaf; there is no old-cluster × new-cluster scan. Each record reference contains membership identity plus exact record revision. Splits and merges are separate lists: `{ab,cd} -> {ac,bd}` correctly produces both. Added/removed leaves are independent of whole-record creation/retirement. These describe changes in supplied navigation inputs, not real-world object deletion, entity equivalence or accepted truth. Input partial status remains explicit. Output items are charged before retention against 32 MiB, including source pins and labels, with a fixed envelope reserve. One bounded item may be constructed before its charge; this is not a whole-process RSS bound. A failure leaves both input hierarchies unchanged.

Five lineage regressions cover crossing partitions, new evidence with stable memberships, isolated/add/remove cases, exact-domain rejection and two disjoint 10,000-node maximum-label snapshots exhausting the output budget. A native engine regression compares ordinary exact queries before/after navigation at levels 0, 1, 2 and 100 for two principals: unrelated predicates, negative claims, half-open time boundaries, isolated nodes and private data retain their original answers. Unfiltered node reads preserve isolated nodes; edge/time-filtered queries retain their documented endpoint selection semantics.

Reproduce synthetic diagnostics:

```sh
cargo run --locked -p weave-cluster --example measure_quality
```

The [recorded output](measurements/2026-09-19-cluster-quality.json) uses 12 named nodes in planted communities, an adversarial bridge, star, chain, ring and isolated fixtures. Pair-F1 compares co-membership with explicitly supplied synthetic labels: `2*TP/(2*TP+FP+FN)`. Internal-link fraction counts each non-self directed link record once; zero denominators are not applicable. Churn counts changed co-membership pairs among common leaves, with added/removed leaves separate. Pair enumeration here is bounded to 12 nodes, not a production quadratic diagnostic API.

At the evidence boundary, two disconnected planted communities score F1=60/60. Adding one bridge eventually joins all 12 nodes and lowers the synthetic score to 60/96; 36 of 66 common leaf-pair memberships change relative to the disconnected input. At shallower levels the report shows distinct scores and churn. These measurements expose limitations of the baseline; they do not establish community-quality guarantees or tune a pass threshold after seeing results.

Fixture exact fallback retains all source relations and explicitly scans the entire source fixture. Navigation has no exclusion certificate and no speedup is claimed. A real exact engine query may span predicates, negative evidence or time selections absent from a positive clustering perspective, so fallback must use its full authorized query domain, not merely `Hierarchy.snapshot()`. Comparing snapshots and reporting lineage does not implement affected-region updates, hysteresis or a durable cluster adapter. Those requirements remain open.


## Authorized native lineage

`Engine::cluster_lineage(before, after, host)` compares two exact `ClusterRequest` values for the same source graph, predicate and context. Each request retains its own revision, valid time and expansion level. Both historical inputs are queried again in one local read transaction under current host authorization; old access does not authorize present disclosure. The service returns a graph with one `cluster_lineage` summary node, not an identity mapping or an accepted equivalence. Its data includes simultaneous splits/merges, overlaps, added/removed leaves and exact source/record revisions.

The native service uses the same leaf extraction and snapshot inputs as navigation. Descriptor/proof pins may add graph domains to `input_snapshots`; they do not add leaf-ID namespaces. The pure `lineage_to_in_domain` entry point requires its caller to establish one leaf domain and current authorization for both inputs. Native execution establishes that boundary by reading one exact graph per side and rejecting different graph IDs. The default pure `lineage_to` remains strict and rejects ambiguous multiple source domains. Neither pure entry point authenticates arbitrary caller-created snapshots.

The summary conservatively depends on every selected source node and positive claim on both sides, with at most 999 combined unique gates including context protection, reserving one pin for repersistence. The capacity is checked before expanding generated nodes and checked again after protection. Generated summary gates and typed-context witnesses survive saving with its readers/carrier removed; private empty contexts still constrain a derived summary. The existing capsule and current-policy resolvers enforce those exact dependencies. A final output budget and the shared operation read budget remain in force. The result always advertises partial scoped coverage; pins supplied by the caller remain observable, and no activity-hiding promise is made.

The service recomputes both frontiers. It does not persist an index, consume incremental change events, apply hysteresis, optimize exact query pruning or implement a language operator. Native tests cover crossing partitions, both historical directions of private data, capsule round trips, empty typed-context influence, current descriptor policy revocation, exact time, missing pins, scope and combined proof limits.
