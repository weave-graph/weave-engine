# Scoped dispatch and effect recovery

The Rust host API in `src/dispatch.rs` installs immutable versioned adapter manifests. Installation pins artifact/configuration identity, principal, graph/branch subscriptions, output grants, effect destinations, lease/retry limits and projection replay mode. It never loads executable code. A changed artifact/configuration requires a new adapter identity and checkpoint; automated state migrations and sandboxed execution remain open.

An adapter moves from installed to running, paused, draining or removed. Polling emits one authorized occurrence at a time with an opaque random lease and a stable replica source/event ID. Full snapshots must be visible to the installed principal before an envelope is delivered; private event counts and global offsets are not exposed. A private durable checkpoint skips unavailable scopes. This conservative whole-snapshot policy is not selective event aliasing or a remote capability protocol.

`complete_handler` commits graph commands, their events, a request-hash-bound processed receipt and the adapter checkpoint in one SQLite transaction. A nested program failure rolls everything back. Redelivery after commit returns the original result without another graph effect; changing commands for the same occurrence is a receipt conflict. Until explicit declassification exists, handler output objects must retain the installed principal's reader restriction. Leases fence stale workers after renewal. Failed deliveries use bounded attempts, exponential backoff with jitter and a durable dead letter requiring explicit replay. Draining accepts current completion without taking new work.

Effect requests persist authorized destination, payload and idempotency key. `begin_effect_dispatch` durably records `unknown` before returning control for I/O. A crash therefore never authorizes an automatic second dispatch. The trusted broker must explicitly reconcile confirmed/failed outcomes using destination evidence. Projection replay cannot request external effects. No arbitrary external transport executes inside this API, and no exactly-once guarantee for remote systems is claimed.

`examples/dispatch_probe.rs` is a host test driver. With the explicit `recovery-testing` build feature, `crash_before_commit` exits after graph/receipt/checkpoint writes but before the outer commit. `crash_after_commit` exits before acknowledgment. The normal library has no environment-triggered failpoints. Independent `scripts/root_dispatch.py` exercises process death before commit, after commit/before acknowledgment, lease renewal, duplicate receipts, request conflicts, lost intent acknowledgment and unknown effect recovery.

Remaining E05/E06 work includes fine-grained event schemas/transaction ordinals, causal loop budgets, durable timers, retention and lost-replay policies, concurrent runner isolation, signed capability revocation, automated adapter upgrades, and actual destination-specific effect adapters. The current bounded polling page/backpressure check does not bound total historical journal size; it conservatively suspends a consumer when a scanned page already exceeds its backlog limit.


Completed-handler receipt retries recheck the current event source scope and every cached query result's current identity, descriptor and source-proof authority. A handler may have read graphs unrelated to the event, so event authorization alone is insufficient. The check runs in the receipt transaction and shares the operation read budget; stored result text is bounded in SQL before allocation. Receipt replay never reruns graph writes or external effects.
